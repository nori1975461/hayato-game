# ヒット演出制御モジュール仕様（イース風の打撃感）

対象: `vortex/`（クルット・モビット）
実装: `vortex/src/systems/hitfx.js`
状態: **モジュール作成済み・ゲーム本体への組み込みは未実施**（既存ファイルは1行も変更していない）

---

## 1. 目的

イース（Falcom）系アクションの「当たった瞬間に画面ごと殴られる」打撃感を、
特定のゲームエンジンに依存しない形で再現する。要素は4つ。

1. ヒットストップ — 命中の一瞬だけ時間が止まる
2. 画面振動 — 描画基準座標を短時間ランダムに揺らし、減衰して0へ戻す
3. ヒット演出 — 対象の白フラッシュ＋命中座標の火花
4. SEピッチ揺らぎ — 同じ音の連打が機械的に聞こえないよう±5%でばらす

この4つは**単独では効かず、同時に発火して初めて「効いた」と感じる**。
よって統合エントリ `hit()` を1つ用意し、強さ `power`(0..1) だけで全パラメータを比例させる。
軽い攻撃と重い一撃の差が、呼び出し側の数値1つで表現できる。

## 3. 最重要の設計制約: 決定性

**このプロジェクトは `Math.random()` を禁止しており、共有RNG `run.rng` の消費順が変わると
seed固定の自動テストが壊れる。** 過去に実際に踏んだ罠（ヒットマーク間引きで rng を使いかけた件）。

汎用のヒット演出モジュールは「ランダムな振動」「ランダムなピッチ」を素朴に `Math.random()` で
実装するため、**そのまま持ち込むと必ずこの制約を破る。**

### 解決

モジュールは**専用の独立乱数ストリーム**（mulberry32・`core/rng.js` と同式）を内蔵する。

- `run.rng` を1回も引かない → 既存の autotest 決定性は完全に無傷
- seed 固定なら揺れもピッチも完全再現する → 演出自体もテストできる
- `config.random` で外部の乱数関数へ差し替え可能（他プロジェクトへ持ち出す場合）

実測: 100回の `hit()` + `update()` で共有RNG呼び出し **0回**（§7の検証済み）。

## 4. エンジン非依存の構造

`hitfx.js` は Phaser / DOM / Web Audio / `window` を**一切 import・参照しない**。
外界へ触る操作はすべて `host` アダプタ経由にする。

```
                 ┌─────────────────────────┐
  ゲーム側  ───▶ │  hitfx（純JS・状態のみ） │ ───▶ host アダプタ ───▶ Phaser / Web Audio
   hit()         │  時間と「見た目の指示」   │      （エンジン依存はここだけ）
                 └─────────────────────────┘
```

`host` のメソッドはすべて任意。渡さなくても状態ポーリングだけで動く。

| メソッド | 呼ばれるタイミング | 役割 |
|---|---|---|
| `applyShake(ox, oy)` | 毎 `update()` | カメラ基準座標へ振動を適用 |
| `setFlash(target, on)` | フラッシュ開始/終了時のみ | 対象を白く塗る／戻す |
| `spawnSpark(x, y, info)` | `hit()` / `spark()` | 火花を出す |
| `playSound(name, pitchMul, info)` | `hit()`（`sound` 指定時） | SEをピッチ倍率つきで鳴らす |

`setFlash` が**状態変化時にしか呼ばれない**のは、毎フレーム `setTint`/`clearTint` を叩くと
描画コストが無駄になるため（現行実装は毎フレーム叩いている）。

## 5. API

```js
import { createHitFx } from './systems/hitfx.js';

const hitfx = createHitFx({ seed: 42, host, config });
```

### メインループへの組み込み

```js
// 毎フレーム
hitfx.update(dt);                        // ← 停止中も必ず呼ぶ（止めると永久に解けない）
if (hitfx.frozen) { draw(); return; }    // ゲーム進行だけを止める
updateGame(dt);
draw();                                  // 描画基準座標へ hitfx.offset を加算
```

### 命中時

```js
hitfx.hit({
  x, y,              // 命中座標（火花の発生位置）
  power: 0.8,        // 0..1。これ1つで停止時間・振幅・火花数がすべて比例する
  target: enemy,     // 白フラッシュさせる対象
  scope: 'global',   // 'global'=全体停止 / 'target'=その対象のみ停止
  color: 0xffe9a8,   // 火花の色
  angle,             // 攻撃方向（ラジアン）
  sound: 'hit',      // SE名（ピッチは自動でばらつく）
});
```

戻り値は実際に発火した内容 `{ power, stopSec, shakeAmp, sparkCount, pitchMul }`（テスト・ログ用）。

### 個別API

| メソッド | 説明 |
|---|---|
| `hitStop(sec, target?)` | 停止をかける。`target` 省略で全体 |
| `isFrozen(target?)` / `frozen` | 停止中か |
| `shake(amp, dur?)` | 振動をかける |
| `offset` | 現在の振動オフセット `{x, y}` |
| `flash(target, sec \| {frames} \| {sec})` | 白フラッシュ |
| `isFlashing(target)` | フラッシュ中か |
| `spark(x, y, info)` | 火花のみ |
| `pitch()` | ピッチ倍率 0.95〜1.05 |
| `detuneCents()` | Web Audio の `detune` 用セント値 |
| `forget(target)` | 撃破・退場した対象を忘れる（参照リーク防止） |
| `reset()` | 全状態を破棄（シーン再開始時） |

## 6. 4機能の仕様

### ① ヒットストップ

- `power` 0→`0.03`秒 / 1→`0.06`秒 を線形補間
- **多段ヒットは加算せず「長い方を採用」**。同時に何十発当たっても固まらない
- 累積上限 `cap = 0.12` 秒でさらに頭打ち（実測: 50連続ヒットでも 0.067 秒）
- `scope: 'target'` で対象だけを止められる（全体は動いたまま敵1体が固まる表現）

> 加算にしないのは既存 `freezeT = Math.max(freezeT, …)` と同じ思想。実装揺れを作らない。

### ② 画面振動

- 振幅 `power` 0→`2`px / 1→`9`px、持続 `0.18` 秒
- 減衰は **ease-out（残り時間の2乗）** — 開始直後が最も鋭く、終わり際は静かに0へ収束
- 1フレームの最大変位を `maxOffset = 14`px でクランプ（画面外が見えるのを防ぐ）
- **重複時は「いまの実効振幅が強い方が勝つ」**。弱く長い揺れが強い一撃を食い潰さない

```
振幅
 │╲
 │ ╲___          ← ease-out: 立ち上がりが鋭く、尾を引かない
 │     ╲____
 └──────────── 時間 (0.18s)
```

### ③ ヒット演出

**白フラッシュ**
- 既定 `0.05` 秒。`{frames: 2}` 指定も可（60fps換算の**実時間**へ変換）
- フレーム数で持たせないのは、144Hz環境で `2フレーム = 0.014秒` となり見えなくなるため
- 期限切れで Map から自動削除 → 死んだ敵の参照が残らない

**火花**
- 発生数は `power` 0→`4`個 / 1→`12`個
- 実際の描画は host に委譲（vortex では既存の `fx.hitSpark` のプールを再利用できる）

### ④ SEピッチ揺らぎ

- 倍率 `1 ± 0.05`（実測レンジ 0.9500〜1.0500）
- `detuneCents()` で Web Audio の `detune`（セント）へ変換 — vortex の `tone()` は
  `detune` パラメータを既に持っているので、**合成音のままピッチをずらせる**
- 呼ぶたびに必ず変化（実測: 連続20回すべて異なる値）

## 7. 検証結果（実測）

`node --check` 通過。機能検証 **29項目すべて合格**。

```
ok   ①power=1 は約0.06秒で解ける          -> 0.0667s / 期待0.06s
ok   ①power=0 は約0.03秒（強さで伸縮する）  -> 0.0333s
ok   ①50連続ヒットでも cap 0.12秒を超えない -> 0.0667s
ok   ①scope=target は全体を止めない
ok   ②時間経過で減衰する(ease-out)         -> 早期4.68 → 後期0.11
ok   ②最終的に0へ戻る
ok   ②強い一撃が弱い長時間の揺れを上書きする
ok   ③既定0.05秒で解除される
ok   ③解除後にMapへ死んだ参照が残らない
ok   ③火花数が強さで増える                 -> power0→4個 / power1→12個
ok   ④±5%の範囲に収まる                   -> 0.9500 〜 1.0500
ok   ④連続呼び出しで毎回変わる
ok   同一seedで完全に同一の系列
ok   共有rngを一切消費しない                -> 共有rng呼び出し 0回
ok   停止が必ず解ける（無限フリーズしない）
```

検証スクリプトはスクラッチパッド（`hitfx-verify.mjs`）。恒久化するなら `vortex/dev/` へ移す。

## 8. vortex への組み込み案（未実施・承認待ち）

既存の打撃感を壊すリスクがあるため、**ゲーム本体は未変更**。組み込むなら以下の順。

### 段階1: ④SEピッチ揺らぎだけ入れる（最も安全・効果が大きい）

未実装の唯一の項目で、他の挙動に影響しない。

- `sound.js` の `tone()` 呼び出しのうち**ヒット系SEのみ** `detune` に `hitfx.detuneCents()` を加算
- 対象候補: `heroPunch` / `pop` / `hurt` / `hit`
- BGM（`bgmGain` 系）には**絶対に入れない**（音痴になる）

### 段階2: ①②③を hitfx 経由へ寄せる

- `Run.js` の `freezeT` / `shake()` を `hitfx` の薄いラッパへ差し替え
- 敵・ボス・主人公で3重になっている `flashT` を `hitfx.flash()` へ統合
- `killEnemy` / `despawn` で `hitfx.forget(e)` を呼ぶ
- host アダプタは `Run.js` 内に定義（`applyShake` は `cameras.main` へ、`spawnSpark` は既存 `fx.hitSpark` へ）

### 注意点

- **`power` の割り当て設計が体感を決める。** 現行の被弾は `ratio = dmg/maxHp` を使っており、
  この考え方をそのまま `power` に流用できる
- 段階2は**打撃感が変わる＝ユーザー目視での確認が必須**。数値だけでは合否を判断できない
- ヒットストップは子ども向けとして長すぎると「重い・もっさり」になる。0.06秒上限は妥当だが実機確認が要る
