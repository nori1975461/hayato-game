# R21 Wave 2 ―「よろけブレイク」設計記録

2026-08-21 実装。`docs/hit_effect_spec.md`（打撃演出の下地）の続き。

このゲームの**合格基準は2つだけ**である（ユーザー指示・2026-08-20）。

> 「なにより重要なのは、**『攻撃の体感（爽快感）、攻撃を受けた緊張感』を最大化すること**。
>  それがダメならこのゲームは失敗。そういえるほど重要。」

以下すべての設計判断は、この①②のどちらをどう上げるかで決めている。どちらも上げない項目は、
技術的に正しくても入れていない。

## 1. 何が壊れていたか（実測）

Wave 1 で打撃演出（画面振動・ヒットストップ・命中音・つぶれ・ダメージ数字）を入れたが、
ユーザー評価は「まだ弱い。とうてい納得いくレベルではない」だった。演出の調整不足ではなく
**構造の問題**だったことが、CDP実測（seed=42・自動操縦・396秒・例外0）で確定した。

| 実測項目 | 値 |
|---|---|
| 仲間の加害距離 | 中央値 **180px** / p90 **314px** / 最大 **538px**（拳は78px） |
| 画面内の最大距離（view 640×360・カメラ追従） | 約 **367px** |
| 遠距離フォームで過ごす時間比 | **85.7%**（`weaponLevel 11` 到達＝94秒以降ラン終了まで固定） |
| 終盤の撃破シェア 主人公 | **37.9%**（序盤74.2%から単調減少） |
| 終盤のダメージ配分 仲間 | **70.4%** |
| **HPが30%を下回った時間** | **0秒**（15%未満も0秒・死亡0） |
| 被弾頻度 | **12.5秒に1回**（開始54秒は被弾ゼロ） |

**①と②は別々の問題ではなく、1つの原因から出ていた。**
仲間が画面外まで敵を掃除するので、敵が主人公に届く前に消える。
すると**殴る機会と、殴られる脅威が、同時に失われる**。

演出をいくら足しても届かない理由もここにある。演出は「プレイヤーが下した決断」を増幅する装置であり、
決断そのものは作れない。1回の攻撃に対してプレイヤーが行っている入力が0回なら、何倍しても0である。

## 2. なぜ「距離で分ける」ではないのか

当初の統合案は「半径Xまでは自動の担当／その外は手動の担当」という空間分割だった。
**これは実測により原理的に不可能と確定した。**

- 手動担当帯として確保しようとした 140〜220px は、**仲間が加害する距離の中央値（180px）そのもの**
- 飛距離を決めているのは `archetypes.SHOT.range` **ではない**。`Run.js` の弾の `life: 1.1` × 弾速
  （wl12 で 414px/s）＝ **455px** であり、`range` は `orbit.js` の**索敵にしか使われていない**
  （実測の p90 314px が range 220px を94px超えていたことがそのまま証拠）

これは過去の失敗「自分のキル圏の内側を判定に使う仕組みは成立しない」（アームスラムが84秒に1回しか
発動しなかった件）の、半径を広げた再演でもある。

⇒ **分けるのは距離ではなく「とどめの権利」にした。** 排他の条件式に距離項が1つも無い。

## 3. 中核：とどめの関門

```js
// Run.dealDamage（敵HPを減らす唯一の場所。e.hp -= dmg は全コードで1箇所しかない）
if (e.stag && src !== 'manual') return;          // よろけ中は仲間・自動拳が通らない
...
if (willKill) {
  if (src === 'manual' || e.isBoss || e.rebooted) this.killEnemy(e, color, src);
  else { e.hp = 1; this.enterStagger(e); }       // ★仲間と自動拳はとどめを刺せない
}
```

`src` の3値：`'manual'`（手動の一撃＋必殺）／`'hero'`（自動拳）／`'ally'`（仲間）。

**撃破の経路は3つしかない**ので、関門はこれで漏れない。

| 経路 | 帰属 |
|---|---|
| `dealDamage` の `willKill` | `src` で判別 |
| `special.js` の雑魚即死 | `'manual'`（手動発動） |
| `Run.js` の bomba 自爆 | `'self'` |

### よろけ（`BALANCE.stagger`）

HPが尽きた敵は倒れずに**青白く光って漂う**。

- 移動 ×0.55。**攻撃はやめるが、接触ダメージは維持したまま主人公へ歩き続ける**
  （★当初は「攻撃をやめて待つ」設計にしたが、それは②の緊張感を下げるので撤回した）
- 4.5秒放置すると**復帰**（HP45%・速度1.25倍・ダメージ1.25倍・赤）。復帰体は二度とよろけない
  ＝仲間が普通に倒せる（詰み防止の安全弁）。報酬はXPのみで、コア・回復・必殺ゲージは出ない
- 手動で割るとXP2倍。**炸裂が周囲のよろけへ連鎖する**（半径76px・減衰0.92・最大6段）
  ＝単体を叩くより群れの中心を叩くほうが得

### これが解いていること

**「仲間が強い＝主人公の出番が減る」という逆相関を、「仲間が強い＝獲物が増える」正の相関へ反転させた。**
獲物の供給量は仲間の稼働量そのもの（実測で仲間は396秒に1242回加害している）なので、
過去の失敗（アームスラム0.71回/分・旧拳0回/40秒）のような「発動しない技」にならない。

また、総撃破数の上限が**プレイヤーの手数**で決まりDPSでは決まらないので、火力過多にもならない。
上手いほど撃破シェアが100%へ近づき、手を止めればよろけが復帰して仲間が拾う＝即死しない。

## 4. 操作系

**新規キーバインドは1つだけ。動詞は3つ。**

| 入力 | 動作 |
|---|---|
| WASD / 矢印 | 移動（従来どおり） |
| **マウス左（押しっぱなしで連射）** | ブレイクストライク（踏み込み突進＋扇96°の一撃＋炸裂連鎖） |
| **J** | 同上のキーボード代替。狙いは最寄りのよろけ→最寄り敵へ自動 |
| SPACE | 必殺（従来どおり） |

- 狙いはカーソル方向。**毎フレーム `getWorldPoint` する**（カメラが遅延追従0.18なのでキャッシュするとずれる）
- 踏み込み突進は左クリックに内蔵。距離は `clamp(標的距離 − 間合い×0.6, 0, 96)` ＝
  近い敵には出ず遠い敵には出る＝1入力で射程が可変になる。突進中は無敵0.14秒
- 空振りは**音も揺れも出さない**。CDは命中0.36秒に対し空振り0.58秒、硬直も0.10対0.30、ヒート−2
  ＝連打を支配戦略から外す

## 5. ②「攻撃を受けた緊張感」

被弾の演出は**すでに手厚かった**（`hitPlayer`：専用音・画面振動5〜9px・赤フラッシュ＋方向表示・
ヒットストップ最大0.12秒・ノックバック・ヒート半減）。足りなかったのは演出ではなく**脅威そのもの**。

| 手当て | 内容 |
|---|---|
| 仲間の掃除範囲 | `allyMaxReach 132px`。弾は `Run.updateBullets` でリーシュ、近接系は `orbit.rebuild()` 末尾で一括クランプ（合成倍率で個別値が溢れるので、数値表ではなくクランプが正典） |
| 無敵時間 | `invulnSec` 0.8 → **0.55**。0.8秒×120px/s＝96px ぶん群れを素通りできていた |
| 回復過多 | 「たいりょく+35」が最大HP増と35回復を兼ねていた → 回復は増分の30%へ。5レベル毎の全回復も40%へ |
| 開幕の無風 | `spawnIntervalStart` 1.15 → 0.95／開幕の湧きに snipa を15%混ぜる |
| 射手の圧 | `allyMaxReach 132` により snipa/turret が**構造的に仲間の圏外**になる（turret の滞空を160へ）。プレイヤーが出向かないと黙らない敵 |

### ★設計原則：振幅は頻度と逆相関で設計する

被弾の**9px は酔わない**（稀だから）。一方 Wave 1 のプリセット4の**攻撃時8px は「いきすぎ・酔う」**と
実プレイで判定された（毎秒1〜3回起きるから）。

⇒ 自動の牽制 **0px** ／ 手動の通常ヒット **5px** ／ ブレイク **6px** ／ 連鎖3段以上 **7px** ／ 被弾 **9px**。
`freezeCapSec 0.16` も新設した（従来ヒットストップに上限が無く、被弾の0.12と重なると渋滞していた）。

## 6. 仲間の扱い（弱くはしていない）

**単純な弱体化はユーザーが明確に却下している。**弱くしたのは**射程だけ**で、火力・装飾6ティア・
進化・合成はすべて据え置き。安全網は無傷のまま、役割だけを「火力」から「獲物の生産設備」へ翻訳した。

### フォームの往復を直した

```js
// 旧: formIndexFor(lv) = floor((lv - 1) / 2) % 2
// 新: formIndexFor(i, t) = (floor(t / formCycleSec) + i) % 2
```

旧実装は `maxLevel 12` が帯5（遠距離）に当たるため、`weaponLevel 11` 到達（実測94秒）以降
**ラン終了まで遠距離に固定**されていた（時間比85.7%）。`maxLevel` を13にしても
`formIndexFor(13)=0` で今度は近接に固定されるだけで直らない。
**問題はパリティではなく「単調増加して飽和する変数の関数であること」**だった。

時間と個体番号で決めることで、`run.rng` を消費せず（シード固定テストを壊さず）に往復が復活する。
`+i` により**常にパーティの約半分が近接**＝誰かが必ず主人公の隣で殴っている絵になる。

### 対ボス倍率の非対称を反転

`orbit.js` に `isBoss`/`bossMul` は**1件も無く**、一方で主人公は拳・ワイヤーアーム・アームスラムが
すべて `bossMul 0.5` だった。つまりボス戦は「**手動だけが半減し、全自動は減衰なし**」という、
方針と真逆の構造だった。`orbit.bossMul = 0.12` を新設し、`hero.strike.bossMul = 1.0`（手動だけ等倍）とした。

ボスに**よろけは持ち込まない**（独自のライフサイクルとHPバーを壊すため）。代わりに
**予告ブレイク**：予告中のボスへ手動の一撃を当てると割り込め、1.4秒のあいだ手動ダメージ2.4倍。

## 8. 残る未検証事項（すべて推測・実プレイで確認すること）

1. **連鎖の平均段数**。8段を超えると1クリックの重みが薄れ、2段を下回るとクリック疲れになる。
   `burstRadius 76` と `stagger.speedMul 0.55` は机上では決められない
2. **よろけと健常が実プレイの等倍で見分けられるか**。青白tint＋収縮リング＋速度低下の3チャネルだが、
   拡大PNGではなく**640×360の等倍**で周囲との相対輝度を測って判定すること
3. **`invulnSec 0.55` が理不尽にならないか**。よろけが10体以上滞留する局面（ラッシュ＋エリート）と
   重なったときが未計測
4. **リブート体の雪だるま**。cap張り付き（220体）とラッシュが重なると赤い強化体が積み上がりうる
5. **フォーム11秒周期の体感**。「賑やかで良い」か「落ち着かない」かは未検証。
   ゲーム内で 7 / 11 / 17 を切り替えて選んでもらうのが最速
6. **`allyMaxReach 132` の体感**。仲間が至近でしか働かない絵が「一緒に殴っている」と読めるか、
   「弱くなった」と読めるか
7. **必殺技との噛み合わせ**。ゲージが手動撃破でしか溜まらないので自己制限が効く、というのが本設計の
   判断だが、「よろけを溜めてSPACE」が有利すぎないかは未計測

## 9. 追検証（Wave 2 実装後・2026-08-21）

実装後にヘッドレス実測を重ねた結果、**§7 の数値の一部が計測器の欠陥によるもの**と判明した。
ここに何が誤りだったか、何が本当の問題だったかを残す。数値そのものより、**どう間違えたか**が再利用可能な情報。

### 9.1 計測器の欠陥を4件出した

| 欠陥 | 何が起きたか | 直し方 |
|---|---|---|
| 無敵の二重計上 | 被弾フックが `player.invuln` しか見ず、踏み込み突進の無敵 `_strikeIfr`（`Run.js:421` で同じく早期return）で弾いた分を実ダメージに計上。一撃151回/分×0.14秒＝時間の最大35%が無敵なので、**被弾回数とダメージが3.4倍に膨らんでいた** | 「HPが実際に減ったか」で判定する。無敵の条件が将来増えても壊れない |
| ボスを加害者候補から除外 | 加害者の同定で `e.isBoss` を弾いていたため、被弾37回すべてが「その他」に落ち、**死因が一切見えなかった** | ボスも候補に入れる。加害者の同定は `origHurt` を呼ぶ前に済ませる（bomba は自爆で消えてから殴るので後から探すと必ず取り逃す） |
| Node変数をブラウザ側から参照 | 計測器に足した打撃間隔の下限 `GAP` はNode側の変数。ブラウザ内で走るコードから参照して `ReferenceError` になり、**ゲームが5.7秒で停止したまま数値だけ出ていた** | INSTALL文字列はテンプレートで値を埋め込む |
| 連続実行時のポート競合 | 前のシードの `chrome.kill()` 直後はデバッグポートが解放されておらず、12秒のリトライを使い切って `wsUrl` が null のまま `new WebSocket(null)` で落ちる | 起動前にポート解放を待つ／リトライ30秒／失敗時は原因の分かる例外 |

**教訓**：`dealDamage` の `willKill` を撃破と数えた過去の失敗（§7）と同じ型が4回起きた。
**計測器はゲーム本体と同じ条件式を使うか、観測可能な結果（HPが減った・敵が消えた）で判定する**こと。
片方だけ直した状態の数値を根拠にバランスを動かしかけた（下記 9.2）。

### 9.2 いったん入れて撤回した調整

水増しされた「被弾48.7回/分・受けダメージ385%/分」を根拠に、無敵0.55→0.7秒・snipa 12→9・turret 11→7・
gareon 18→15・bomba 28→26・`stagger.contactMul 0.55` 新設、という調整を入れた。
計測器を直したところ実際は **被弾11.7回/分・103%/分** で、しかも**健常な雑魚に起因すると同定できる被弾が0件**だった。
調整は動機が消えたうえに②を弱めるだけなので全て撤回した。

### 9.3 本当の問題：主人公の火力の成長曲線が無かった（Wave 2 の回帰）

Wave 2 は撃破を主人公の手動の一撃だけに集約したが、成長曲線は仲間側に残していた。

```
手動一撃 = (34 + 12×(ステージ-1)) × heroMult × ヒート倍率(最大1.4)
  ステージは Lv5→2 / Lv10→3 で打ち止め＝以降 58 で固定
  heroMult を伸ばす通常カードが upgrades に1枚も無い（'atk' は仲間の damageMult）
一方ボスHP = 1800 → 3600 → 6500 → 11000 → 18000 → 28000（15.5倍）
素の手動DPS ≒ 58×1.4÷0.396 ≒ 205 → TTK 8.8/17.6/31.7/53.7/87.8/136.6秒
```

実測でも6走行中5走行が **190〜197秒・3体目のボス（ウズバルカン HP6500）** で死亡した。
対策として `hero`（じぶんの こうげき +35%）を新設して `cycle` 先頭の `atk` と差し替え、
5レベルごとの虹「オールアップ」に `heroMult +0.15` を追加した。
効果：jetviper のTTK 12.0秒→7.7秒、ボス窓のダメージ比 73.4%→65.3%。

**この欠落は数値ではなく構造なので、テストで固定した**：
`balance: autoUpgrade.cycle に主人公の火力(heroMult)を伸ばす項目がある`

### 9.4 ボスの難易度は現在の自動操縦では判定できない

- ボスは `run.enemies` に入る（`boss.js:296`）ので自動操縦から見えてはいる
- しかし退避条件が「HP50%未満かつ最寄り敵90px以内」で、群れの中では最寄りが常に雑魚になる
- ボスの追跡速度は66px/s、プレイヤーは約158px/s。**人間なら振り切れる相手に突っ込んでいるだけ**
- 予告回避もゼロ。全雑魚攻撃・ボス攻撃は0.4〜1.2秒の予告付きで、予告中に動ける距離は48〜111px

よって**ボスHPと `orbit.bossMul 0.12` は触らない**。ここを自動操縦の数値で下げると実機で simply 簡単になる。
判定は息子さんの実プレイに委ねる。

### 9.5 実測で分かった「雑魚帯に緊張感が無い」

| | 時間の割合 | 受けたダメージの割合 |
|---|---|---|
| 雑魚帯 | 約84% | 約25%（健常な雑魚に起因する被弾は0〜1件） |
| ボス窓 | 約16% | **約73%** |

構造的な原因（未対処・次の課題）：

1. 攻撃圏102px＋踏み込み96px＝実効約198pxのキル圏に対し、接触判定は12〜16px。**雑魚は接触する前に死ぬ**
2. ノックバック260×0.12秒＝約15.6pxで、接触帯とほぼ同じ幅を1発ごとに押し戻している
3. よろけは速度0.55倍かつ攻撃停止なので、接触圏へ歩ける個体がさらに減る
4. ボンバの起爆距離 `range: 52` は**自分のキル圏の内側**。過去の教訓（判定半径はキル圏の外に置く）と同じ形で発火しない
5. 射手（snipa/turret）は設計どおりキル圏外に居るが、概算1,200発/420秒に対し命中16発＝**変換率約1%**

### 9.7 計測の設計上の注意（次にやる人へ）

- **自動操縦は超人APM**。手動の一撃を151回/分＝2.53回/秒で振っており、命中CD 0.36秒の理論上限2.78回/秒の91%。
  湧きより速く場を掃除するので「雑魚帯が無害」という観測はこの前提に依存する。
  第3引数で打撃間隔の下限を渡せるようにしてあるので、人間近似（約1.25回/秒）でも測ること
- **1シード1走行の比較はできない**。同一ビルド・同一シードでも計測器の重さでフレーム時間が変わり、
  死亡時刻が189.6/191.5/190.2秒、HP<30%の時間が2.9〜7.1%とぶれた
- **死亡後は打ち切る**。実装当初は死亡後も実時間420秒を待ち切っており、1本の半分以上を停止画面の前で浪費していた
