# R23 ―「ボス戦の弾薬」設計記録

2026-08-23 実装。`docs/r21_wave2_break_design.md`（よろけブレイク）の続き。

このゲームの**合格基準は2つだけ**である（ユーザー指示・2026-08-20）。

> 「なにより重要なのは、**『攻撃の体感（爽快感）、攻撃を受けた緊張感』を最大化すること**。
>  それがダメならこのゲームは失敗。そういえるほど重要。」

以下の判断も、この①②のどちらをどう上げるかで決めている。

---

## 1. 何が壊れていたか（実測）

R22 で攻撃の動詞が「ビリヤード攻撃（掴む→溜める→投げる）」に決着し、実プレイでも
「敵が集団で存在している場所に狙って投げれば、より多くの敵を倒せる戦術が生まれる」と確認された。

ところが**ボス戦だけ、その動詞が成立しない**。理由は構造にある。

- 投げの弾になれるのは**よろけた敵**だけ
- **ボスはよろけない**（独自のライフサイクルとHPバーを壊すため、R21W2で意図的にそう決めた）
- ボス戦中の雑魚湧きは `boss.trashInterval 2.4 / trashCount 1` × `billiard.spawnMul 0.70`
  ＝ **3.4秒に1体**（ボスへ集中させるための意図的な絞り・§10.4）

つまり「ボスへ集中させる」設計と「弾は雑魚から採る」設計が正面から衝突していた。

### 実測（`scratchpad/cdp-r23-boss.mjs` seed=42・400秒・無敵・例外0・帰属不明0）

| 項目 | 実測値 |
|---|---|
| 投げの回数（平時） | **44.0回/分** |
| 投げの回数（ボス戦中） | **20.0回/分**（平時の45%） |
| ボス戦中の場のよろけ | 平均 **0.03〜1.24体** |
| ボス戦中の掴める距離のよろけ | 平均 **0.02〜0.78体** |
| ボス戦が占める時間 | 329秒中 **171秒＝52%** |
| ボスの予告（＝ブレイクの機会） | **18〜21回/分** |
| ブレイク成功 | **2〜6回**（1ボス戦あたり） |

ボス別の与ダメ内訳（throw / jab / ally / hero）：

| ボス | HP | 決着 | 投げ | 突き | 仲間 | 自動拳 |
|---|---|---|---|---|---|---|
| コロガンナー | 1800 | 21秒で撃破 | 72% | 4% | 17% | 7% |
| ジェットバイパー | 3600 | 50秒で撃破 | **33%** | 14% | **36%** | 17% |
| ウズキング | 6500 | 20秒で撃破 | 84% | 2% | 10% | 4% |
| ウェイブロード | 11000 | 51秒で撃破 | 71% | 6% | 16% | 7% |
| ミサイルガ | 18000 | 29秒で未決着 | 72% | 4% | 18% | 7% |

**読み取れたこと。**

1. **プレイ時間の半分（52%）がボス戦**。ここで動詞が半減するのは「たまに起きること」ではない
2. 弾さえあれば投げは主役になる（72〜84%）。**足りないのは威力ではなく弾薬**
3. 弾が特に枯れたジェットバイパー戦（よろけ平均0.03体）でだけ、**仲間(36%)が投げ(33%)を上回った**
   ＝ ①の主役が自動層に移る。これは R21W2 で「とどめの権利」を作って解いたはずの失敗の再発
4. **予告は19〜21回/分もあるのに、ブレイクは1戦あたり2〜6回しか出ていない**

## 2. なぜ「湧きを増やす」ではないのか

`trashInterval` を下げれば弾は増える。しかしそれは §10.4「ボス戦中はラッシュを起こさず、
雑魚を絞ってボスへ集中させる」を正面から壊す。ボス戦が雑魚処理ゲームになり、
**ボスという脅威が薄まる＝②を下げる**。①のために②を削るのは、この2つが並列である以上できない。

⇒ **弾はボス自身から出すことにした。**

## 3. 中核：予告を割ると装甲が剥がれる

```
予告を見る → 近づいて突きで割る（②のリスク）→ 装甲が剥がれる → 拾って投げ返す（①）
```

この4手はすべて**既存の動詞と既存の記号**だけでできている。プレイヤーが新しく覚える語彙はゼロ。

- 「予告」＝ 既存のボスの予告演出
- 「突きで割る」＝ R21W2 で作った `breakTelegraph`（ただし後述の欠落があった）
- 「装甲片」＝ **よろけ状態のチビット**。ボスの `summon` が撒くのと同じ敵なので、正典の上でも
  実装の上でも既存資産。青白のよろけリング＝「これは自分の獲物」という記号もそのまま使える
- 「拾って投げる」＝ 雑魚とまったく同じ操作

実装は `systems/billiard.js` の `dropShards` / `breakBoss`、パラメータは `balance.js` の
`hero.billiard.shards`。

### 併せて直した欠落

**ビリヤードモードでは、突きでボスの予告を割れなかった。**

一撃モードの `Run.doStrike` は `this.boss.breakTelegraph()` を呼ぶが、`billiard.js` の突きには
その経路が無く、ボスを割れるのは**投げの着弾だけ**だった。弾が枯れているボス戦では、
弾薬供給とカウンターのチャンネルが**同時に**閉じていたことになる。

「予告を割る権利は突きが持つ」というR22の記録は、実際には**雑魚の予告（`e.atkState`）にしか
効いていなかった**。ボスの予告はボス側の内部ステートなので、別の経路が要る。

### 設計上の歯止め

- 装甲片は `noReward`（経験値もジェルも出さない）。弾薬の供給が経験値の蛇口になると、
  ボス戦が稼ぎ場に変わる
- 装甲片は**主人公とボスの間**に撒く。拾いに行く動きが「ボスへ近づく」と同じ向きになる＝
  弾を集めるほど②のリスクを取ることになる（逃げ得にしない）
- 拾わなければ4.5秒で静かに消える（既存のよろけの時間切れ＝消滅と同じ）
- `enemyCap` に当たったら諦める。弾薬のために上限を破らない

## 4. 実測（変更後）

同じ条件（seed=42・400秒・無敵・例外0・帰属不明0）。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 投げの回数（ボス戦中） | 20.0回/分 | **50.0回/分** |
| 投げの回数（平時） | 44.0回/分 | 40.4回/分 |
| ボス戦中の場のよろけ | 平均 0.03〜1.24体 | **0.66〜1.32体** |
| 掴める距離のよろけ | 平均 0.02〜0.78体 | **0.46〜1.20体** |
| 投げの与ダメシェア | 33〜84% | **87〜90%** |
| 仲間の与ダメシェア | 10〜36% | 6〜10% |
| ブレイク成功（1戦あたり） | 2〜6回 | 2〜8回 |
| ボス戦の合計時間 | 171秒（撃破4/5） | **67秒（撃破5/5）** |

**ボス戦での投げが平時を上回った（50.0 > 40.4回/分）。** 「山場でだけ動詞が半減する」は解けた。
弾が枯れていたジェットバイパー戦は、投げ33%・仲間36%（仲間が主役）から、投げ90%・仲間7%になった。

### ⚠️ この数字は期待値ではなく上限値

ボットは**ボスの隣に立って0.36秒ごとに突き続ける**（無敵なのでそれができる）。結果、
ミサイルガ戦では予告10回のうち**8回**を割っている。実プレイの小6がこの割合を出すことはない。
ブレイクの回数がそのまま弾薬と `bossBreakMul 2.4` の持続に直結するので、
**この上限値を根拠に倍率を下げると、実プレイの体験を落とす方向へ外す。**

⇒ 数値を確定せず、ゲーム内キー**9**で「切（R23前）／弱／標準／強」を切り替えられるようにした。
   手触りの正典は息子さんの実プレイ（プロジェクトの恒久原則）。

| キー9のモード | 1回のブレイクで落ちる数 | ボスへの倍率 |
|---|---|---|
| 標準（既定） | 2個 | ×2.5 |
| 強 | 3個 | ×4.0 |
| 切（R23前） | 0個 | ―（装甲片が出ない） |
| 弱 | 2個 | ×1.5 |

### 見るべき副作用

- ボス戦の合計時間が 171秒 → 67秒（プレイの52% → 21%）。ボスが「脅威として振る舞う時間」は減る。
  ただし被弾は67秒のボス戦で69回＝ほぼ毎秒1回あり、②が薄くなったわけではない
- 仲間の与ダメが 6〜10% まで下がった。R21W2 で「仲間が主役」を失敗と決めた以上これは設計どおりだが、
  仲間を入れる意味が痩せて見えるなら `orbit.bossMul`（現行0.12）が次の調整点

## 5. 検証スクリプト

```bash
node vortex/scratchpad/cdp-r23-boss.mjs [seed] [秒] [god|nogod]
```

⚠️ **既定は無敵（god）**。測りたいのは弾薬供給であって生存ではない。無敵にしないとボットが
ボスに密着して死に、後半のボス戦を一度も観測できない（初回実測は66秒で死亡し、6体中1体しか測れなかった）。

⚠️ **計測器の欠陥をここで1つ潰している**。`hitPlayer` は無敵中でも呼ばれて中で弾かれるので、
**呼び出し回数を数えると被弾が桁で膨らむ**（171秒のボス戦で1676回＝毎秒9.8回。無敵0.55秒なら
上限は1.8回/秒のはず）。HPが実際に減った呼び出しだけを数える形に直した。
→ 「計測器はゲーム本体と同じ条件式か、観測可能な結果で判定する」（2026-08-21の教訓）の再発。
