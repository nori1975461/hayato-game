# R28 らいこうだん・ほのおだんを「派手すぎるくらい」にする

実プレイFB（2026-08-23）:
> 雷光弾の効果音をもっと派手に。弾が飛んでいくときに稲光のエフェクトと音。
> 当たったときも当たった音と一緒に雷の音も。派手すぎるぐらいでいい。炎熱炸裂弾も同様に。

## 1. なぜ「遠慮しない」でいいのかを先に測った

演出の振幅は**頻度から逆算する**（報酬・演出を足す前に、その軸が飽和していないかを測る）。
特殊弾がどれだけ稀かを 300秒の自動プレイ（seed=42 / 無敵 / `cdp-r28-spec.mjs`）で実測した。

| 出来事 | 回数 | 頻度 |
|---|---|---|
| らいこうだん 受取 | 2回 | 150秒に1回 |
| らいこうだん 命中 | 2回 | 150秒に1回 |
| ほのおだん 命中 | 1回 | 300秒に1回 |
| マグマン 掴み | 1回 | 300秒に1回 |

＝ **1回のプレイで数回しか起きない**。ここは「うるさい」より「一生に何度も見ない絵」を優先する帯。
ふだんの撃破（テトリスの連打＝R27）は毎分20回起きるので抑制が要るが、この弾は逆。

## 2. 何を足したか

**共通の考え方**：飛行中は「まだ来ていない」を鳴らし続け、着弾は「別物」に切り替える。
雷と炎で**語彙を変える**（雷＝裂ける／炎＝膨らんで燃え続ける）。同じ演出にすると2種類ある意味が消える。

### らいこうだん（bolt）
- 飛行中：`boltFly` を 0.11秒ごと（強さ0.45〜1.0・音程0.88〜1.14でランダムに揺らす。固定だと機械の警報音になる）
- 飛行中：0.22秒ごとに画面を明滅（`flyFlash 0.10`）／前方へ伸びる稲妻／`flyReach 150px` 内の敵へ**当たっていない放電**を2本
- 着弾：落雷の柱 3→**6本**（26ms差で落とす）＋放射状の枝**8本**＋**画面を横切る1本**（カメラの映っている範囲で引く）
- 着弾：白 0.5 →（90ms後）金 0.34 の**2段フラッシュ**（本物の雷は一度光ってから空が明るくなる）
- 着弾：`thunder(1)` ＋ `bigBoom(1)` ＋ 150ms後に `thunder(0.55)`（遅れて届く2発目）
- 雑魚に当たったときも `thunder(0.30)` と `boltFly` を重ねる（＝通常の弾と音で区別が付く）

### ほのおだん（blast）
- 飛行中：`blastFly` を 0.12秒ごと／0.26秒ごとに明滅／**通った跡に火柱**（軌跡が燃えている）
- 着弾：火柱 1→**5本**を横に並べる（火の壁）＋放射状の火炎ジェット**8本**（太く短く＝稲妻と別の形）
- 着弾：金 0.42 →（110ms後）橙 0.30 の2段フラッシュ／火の粉 26→**48**＋180ms後にもう26
- 着弾：`fireBlast(1)` ＋ `bigBoom(0.9)` ＋ 220ms後に `fireBlast(0.4)`（まだ燃えている）

### 音そのものの作り直し
- `thunder(power)`：裂ける音を**3段に割る**（バリバリバリッ）／落ちる芯を2本ずらす／転がる余韻を3層（0.06・0.30・0.62秒開始）／小型スピーカー向けに96Hzの倍音
- `fireBlast(power)`：点火→膨らむ火球2層→燃え続ける尾。着弾時のみ爆ぜる粒7発
- `boltFly` `blastFly`：新規。飛行中に鳴らす短い音（雷＝高域のパチッ＋帯電のうなり／炎＝低いゴォ＋パチッ）

## 3. どれだけ派手になったか（前後の差分で測る）

`cdp-r28-fx.mjs`。作業ツリーは壊さず、`OLDBUILD=1` のときだけ R28で触った3ファイルを
`git show HEAD:` の中身で配信して**同じ手順で前のビルドを測る**。
派手さの代理指標は **AudioContext に積まれた音ノード数**（`createOscillator` + `createBufferSource`）。
BGMぶんは同じ長さの無音区間を測って引く。場は空にして（湧きを止め、居る敵を退ける）弾1発ぶんを分離した。

中央値（各3回・`r28fx2.txt`＝旧／`r28fx3.txt`＝新）。EXCEPTIONS は全12+6ランで 0。
命中は毎ラン `boltHits`/`blastHits` が 1 になったことを確認している（＝当たらずに空振りした計測は無い）。

| | 旧 | 新 | 倍率 |
|---|---|---|---|
| らいこうだん 飛行1秒の音ノード（BGMを引いた弾ぶん） | 16 | 93 | **5.8倍** |
| らいこうだん 着弾0.85秒の音ノード | 41 | 141 | **3.4倍** |
| らいこうだん 飛行1秒の絵の数 | 253 | 501 | 2.0倍 |
| らいこうだん 着弾0.85秒の絵の数 | 200 | 421 | 2.1倍 |
| ほのおだん 飛行1秒の音ノード | 15 | 54 | **3.6倍** |
| ほのおだん 着弾0.85秒の音ノード | 44 | 96 | **2.2倍** |
| ほのおだん 飛行1秒の絵の数 | 138 | 251 | 1.8倍 |
| ほのおだん 着弾0.85秒の絵の数 | 156 | 315 | 2.0倍 |

参考：**通常の弾**（特殊でない弾）は飛行1秒で 11ノード。らいこうだんはその8倍以上鳴っている。

## 3-2. ⚠️ 数字が増えても等倍では地味だった（今回いちばん重要な発見）

上の数字が全部2〜5倍になった時点のビルドを **等倍**（実プレイで見えるままの大きさ）で撮ったら、
ほのおだんの着弾は**画面の1/12くらいの小さなオレンジの輪**にしか見えなかった。
原因は大きさでも数でもなく **持続時間**：

- `screenFlash` は 200ms 固定 → 着弾の0.2秒後にはもう光っていない
- 稲妻の寿命が 220〜340ms → 落雷の柱も画面を横切る線も、次のコマではもう消えている
- 火柱は 420msかけて伸びるので、伸び切る前にフラッシュが終わって背景に沈む

そこで**数を増やさずに、規模と持続だけ**を足した：

- `screenFlash(alpha, color, ms)` に持続時間を追加。着弾は 260〜460ms
- らいこうだん：画面を横切る稲妻を1本 → **3本を130ms差**で重ねる／落雷の寿命 340→480ms
- ほのおだん：画面規模の層が無かったので **広がる炎の輪を3枚**（半径120/210/300px・90ms差）を追加。
  火柱は中央だけ2.1倍・間隔を26→42pxに広げて「1本の柱」ではなく「火の壁」にする

この変更で **絵の数はほのおだんで +2 しか動いていない**（313→315）。
＝ **数を数える計測器では、この修正の効果は原理的に見えない**。等倍のスクリーンショットだけが判定手段だった。

## 4. 検証で踏んだ穴（次回のため）

- **autotest では音が一切鳴らない**。`Title.js` は autotest のとき `Sound.init()` を呼ばずに Run へ飛ぶので
  `ctx` が null のまま＝ `sfx()` は全て空振り。音を測るときは autotest を使わず、
  タイトルで SPACE を送って始める（＋Chrome に `--autoplay-policy=no-user-gesture-required`）
- **`Page.captureScreenshot` の `clip` には `scale` が必須**。付け忘れると data が返らない
- **カメラは主人公を追う**ので `BALANCE.view` の座標で線を引くと画面外に出る。
  画面を横切る演出は `run.cameras.main.worldView` を使う（実装中に1件見つけて直した）
- 計測の窓の中でスクリーンショットを撮ると、その待ち時間ぶん音ノードが増えて数字が濁る。
  等倍の絵は `SHOT1=1` の別ランで撮る
