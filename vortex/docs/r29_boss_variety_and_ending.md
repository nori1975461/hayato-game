# R29 — ボス戦BGM／署名攻撃／マオウレクスの弱点コア／エンディング

実プレイFB（2026-08-23）:

> ①ボス戦とマオウレクス戦独自のBGMを作って。ボス戦はポップに。マオウレクス戦は荘厳に。
>  マオウレクスは1.2倍巨大化したうえで、弱点部分を作成し、そこに弾を当てないとダメージを
>  与えられないようにして。
>
> ②マオウレクス以外のボスの攻撃が単調。それぞれ特徴的な攻撃を一種類いれて。特にミサイルガは
>  ビジュアルでミサイルを搭載しているのだから、それを活かした攻撃を。マオウレクスの攻撃は
>  遠距離はミサイルで、近距離はロケットパンチ？と多彩でよい。ただ、ミサイルの速度が遅すぎる。
>  もっと早く。発射音も作って。ロケットパンチも射出音と攻撃音を激しく、そして速度を速くし、
>  攻撃範囲も広げて。**主人公は遠距離攻撃なのだから、マオウレクスの攻撃は遠距離攻撃をしている
>  相手に対して脅威とならないとプレイヤーのクリア意欲を刺激しない。**
>
> ③簡易版でいいのでエンディングをつくって。モビットたちと一緒に宇宙の脅威を倒した！という感じで。
>  ただ簡易版といえど、プレイヤーの満足度が高いものを。HAYATOは簡易すぎているので、あれより充実させて。

## 1. BGM（3曲構成 → 5曲構成）

| 曲 | 前 | 後 |
|---|---|---|
| `boss` | Aマイナー・152BPM・4小節（暗い） | **Cメジャー系・172BPM・8小節（ポップ）** |
| `maou` | （なし。boss を流用） | **新曲。76BPM・4小節・Am-F-G-E（荘厳）** |
| `ending` | （なし） | **新曲。112BPM・8小節・C-G-Am-F / C-F-G-C（凱歌）** |

- ボス戦の「盛り上がり」は**暗さではなく速さと跳ね**で作った。172BPMまで上げ、跳ねるベース・
  裏拍のコードスタブ・手拍子3枚重ね・16分アルペジオ。最後の2小節が C（トニック）へ解決するので、
  ループしても「サビが戻ってきた」と感じられる
- マオウレクス曲は**ポップなボス戦曲との対比が全て**。速さ・跳ね・明るさを全部捨てる。
  76BPM（ボス戦の44%）、ビートを一切置かない（四つ打ちを入れた瞬間ポップに戻る）。
  声部＝パイプオルガンの持続和音／遅れて重なる斉唱パッド／ティンパニ／教会の鐘。
  終止を E メジャー（G# を含むハーモニックマイナーのドミナント）にして厳かさを作る
- 切替は `boss.js` の出現時1行（`cfg.final ? 'maou' : 'boss'`）＝**姿を見る前に耳で格の違いが分かる**

## 2. 通常ボス5体の署名攻撃（1体につき1種類）

「弾が飛んでくるのを避ける」しか無かったのが単調の正体なので、**どれも別の遊びを1つ足す**方針にした。

| ボス | 攻撃 | 足した遊び |
|---|---|---|
| コロガンナー | **ローリングボム** | 転がる爆弾3個→止まった場所に予告円→爆発。*置かれた物から離れる* |
| ジェットバイパー | **フライパス** | 後退して助走→高速で突っ切りながら真横へ弾を落とす。*横へ逃げる* |
| ウズバルカン | **うずまきバルカン** | 主人公を狙わず回りながら3方向の螺旋弾。*走り続ける* |
| ウェイブロード | **つなみウェーブ** | 切れ目が1箇所だけある弾の壁×3。切れ目は波ごとに47°回る。*抜け道を探す* |
| ミサイルガ | **ぜんだんはっしゃ** | 全12発を真上へ打ち上げ→着弾予告→時間差の絨毯爆撃。*足元を空ける* |

- ローリングボムと絨毯爆撃は共通の「着弾予告→時間差爆発」システム（`spawnStrike`）で実装。
  予告円が縮んで着弾点へ収束するので、**残り時間が目で読める**（＝理不尽にしない）
- ミサイルガの着弾点は主人公の**進む先**（`leadSec` 0.55秒後の予測位置）へ寄せる。ただし1発目だけは
  必ず足元に落とす＝「まず一歩動け」が最初の1発で伝わる
- 爆発音と揺れは 0.11秒に1回へ間引く（12発ぶん素通しにすると渋滞して1発も感じられない）

## 3. マオウレクス

### 3-1. 1.2倍巨大化

`spriteScale 8 → 9.6` / `radius 68 → 82`（1.21倍）/ `glowScale 9.5 → 11.4` / `spawnDist 320 → 350`。

### 3-2. 弱点コア（この改修の中心）

胸に露出した炉心。半径27px、本体中心から (x+27, y-25)、左右に ±30px をゆっくり泳ぐ
（phase2 では周期 3.4秒 → 2.1秒に縮んで狙いにくくなる）。

**当たり判定そのものを本体からコアへ移した。** ここが実装上の肝で、素直に
「dealDamage の中でコアとの距離を見る」だけでは**絶対に当たらない**：

- 投げた弾の命中判定は `弾の半径 + 敵の半径` ＝ボス**外周**（中心から82px）で成立する
- コアは中心から約25px の位置にある。つまり外周で判定が終わる限り、弾がコアの座標に到達する
  瞬間は永遠に来ない

そこで `billiard.js` の衝突ループにボス専用の分岐を入れ、**本体は「触れると弾かれるだけの装甲」**、
**ダメージ判定はコア円だけ**にした。装甲に触れた1回だけ「カキン！」を出し、弾は止めずに
奥のコアへ通す。

判定の一元化は `Run.dealDamage(e, dmg, color, src, at)` の `at`（命中座標）で行う。
全経路がここへ合流するので、攻撃側に散らして書く必要がない（散らすと必ず漏れる）。

| 攻撃 | 通るか | 実測 |
|---|---|---|
| 投げた弾・特殊弾がコアに命中 | **通る（×2.4）** | 1000 → **2400** |
| 投げた弾が装甲に命中 | 弾かれる | **0** |
| 素手の一撃・自動拳・オーラ（座標を持たない近接） | 弾かれる | **0** |
| 仲間の弾が装甲に命中 | 弾かれる | **0** |
| 必殺技（爆風。コアが爆心から320px以内） | 通る（倍率なし） | **1000** |

- HPは 28000 → **20000** に下げた。狙う難しさに「長さ」を足すと硬いだけになるため
- 予告ブレイク（＝装甲片＝ボス戦の弾薬の蛇口）は突き／一撃で従来どおり成立する。
  ダメージが通らないだけで、**弾の供給は止まらない**
- 登場イベントに「よわてん：むねの コアを ねらえ！」を追加（`MAOU_INTRO.dur` 3.6→4.4秒）。
  「当たっているのに減らない」は理由が分からないと理不尽にしかならない

### 3-3. 遠距離の主人公に届く攻撃へ

| 項目 | 前 | 後 | 実測 |
|---|---|---|---|
| ミサイル速度 | 180 px/秒 | 340 | **364**（扇状の初速ぶん上振れ） |
| ミサイル旋回 | 70°/秒 | 88°/秒 | 旋回半径 約221px＝横へ切れば抜けられる余地は残す |
| ロケットパンチ 射程 | 210px | **330px** | 実測到達 306px |
| ロケットパンチ 伸長速度 | 640 px/秒 | **1080** | |
| ロケットパンチ 拳の半径 | 16px | **28px** | |
| ダメージ | 64 | 64（据え置き） | プレイヤーHP140 の46%＝満タンから一撃死しない上限 |

音：
- `missileLaunch`（新規）＝点火の破裂＋噴射の吹き出しの2段。斉射では3発ぶんだけ音程をずらして
  重ねる（7発ぶん鳴らすと潰れて1発に聞こえる）
- `rocketHit`（新規）＝金属が拉げる低音＋破断の高域＋長い胴鳴り。`metalSlam` の流用をやめた
- ロケットパンチの射出は `wireShot` に `missileLaunch` を重ねて「ドシュッ！ギュイィン」の2段にし、
  揺れを 120→220、白フラッシュも追加

## 4. エンディング

`Run.endRun(clear)` → **クリア時のみ** `Ending` を挟む → `Result`。ゲームオーバーは従来どおり直行。
payload は素通しなのでリザルトの表示は不変。いつでも SPACE / クリックでスキップできる。

満足度は「長さ」ではなく **自分のプレイが名指しで讃えられること** で作る、を設計方針にした。

1. 撃破の余韻（残り火だけが漂う暗い画面）
2. 「せかいに ひかりが もどった」＋凱歌スタート
3. 「うちゅうの きょういを たおした！」
4. **最後まで連れて行ったモビットを1体ずつ**、名前＋*そのモビットが実際にやったこと*を添えて登場
   （例: ビリッコ「らいこうだんを わたしてくれた！」／マシュモ「いつも きずを なおしてくれた！」）
5. 全員でジャンプ＋紙吹雪「みんなで かちとった しょうり！」
6. この回の記録（時間・撃破数・つかまえた数・コイン）を1行ずつスタンプ表示
7. タイトルロゴ＋THE END → 「SPACE で けっかを みる」

### 実装で踏んだ穴

- **⚠️ 計測器の欠陥（今回いちばん危なかった）**：つなみウェーブを「1発も出ていない」と誤判定した。
  原因は**ボスが主人公に密着していたこと**。ボス弾はボスの中心で生まれるので、主人公が重なって
  いると生成した次のフレームで全弾が主人公に当たって消え、`bulletCount` が常に0になる。
  ボスを210px引き離して測り直したら **19発**（22枠 − 切れ目3枠）と設計どおりだった。
  → **ボス弾を数えるときは必ずボスと主人公を引き離す**
- 弱点コアは「dealDamage で距離を見る」だけでは実装できない（§3-2）。当たり判定の**形**を
  変える必要がある。設定値だけ足して動いたつもりになる典型の罠だった
- 進化形態（evo）は `color` を持たない（基本形から継承する仕様）。`evo.color` を読むと undefined で
  落ちる。Result.js に同じ潜在バグがあったので併せて直した
- Phaser のシーン遷移前に自前で GameObject を destroy して回ると、破棄済みへ二重に触れて
  遷移そのものを落としうる。表示物は `scene.start` の shutdown に任せ、参照だけ捨てる
