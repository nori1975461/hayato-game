## ① いっき撃破の音 — 「本当に差をつけたのか」への答え：**つけていなかった**

### 調べた結果

`BALANCE.crush.presets` が持っていたのは4つだけ。

| 項目 | 標準 | 全開 | ひかえめ | 切 |
|---|---|---|---|---|
| `on` | true | true | true | false |
| `gapMs`（打撃の間隔） | 52 | 44 | 64 | 52 |
| `ring` / `ringFrom`（衝撃の輪＝**絵**） | ○ 3発目〜 | ○ 2発目〜 | × | × |

そして `Run.crushBeat` が鳴らしていたのは全プリセット共通の `Sound.sfx('crush', i)`、
締めは `Sound.sfx('crushEnd', n)`。**音を作っているコードは4つとも1バイトも違わなかった。**

＝ 変えていたのは「1発あたり8〜12msの間」と「絵」だけ。8msは耳では判別できない。
「ほぼ差がなかった」ではなく **差は最初から実装されていなかった** が正しい。

### 直し方：選ぶ軸を「間」から**音色**へ移す

| 名前 | 音の作り | 何が違うか |
|---|---|---|
| **たいこ** | 低いサイン波が落ちる＋倍音の胴＋短いノイズ＋半音ずつ上がる粒 | 従来の打楽器 |
| **ばくは** | 主役が炸裂ノイズ（0.22秒・尾が残る）。**和音を一切持たない**。数を伝える粒は**下がる** | 掘っていく音 |
| **きらきら** | 低音を捨てて金属の音階だけ。五音音階＋非整数倍音（3.01倍）＝ベル | 段差が大きく数えやすい |
| 切 | 従来どおり `pop` 1発 | 比較用 |

### 実測（「別の音になった」の証明）

masterGain に AnalyserNode を分岐で挿し、BGMを止め・ゲームを一時停止して、
50Hz〜16kHz を20本の対数バンドへ畳んだピークスペクトルの L1距離（0＝同一・1＝完全に別）。

```
対照 たいこ vs 切（同じ関数を鳴らす）  1発 0.002   締め 0.028   ← これが測定誤差の大きさ
     たいこ vs ばくは                  1発 0.321   締め 0.204
     たいこ vs きらきら                1発 0.579   締め 0.267
     ばくは vs きらきら                1発 0.607   締め 0.388
```

対照（同じ関数どうし）の 0.002 に対して 0.20〜0.61。**誤差の10〜300倍**離れている。

帯域の内訳（1発ぶん・低60-200Hz / 中200-2k / 高2k-12k）:

| | 低 | 中 | 高 | 重心 |
|---|---|---|---|---|
| たいこ | 24% | 41% | 36% | 2181Hz |
| ばくは | 15% | 21% | **64%** | 4039Hz |
| きらきら | **1%** | **74%** | 25% | 2129Hz |

⚠️ 最初の測定はBGMと敵の音が混ざっていて、**同じ関数どうしでも数字がずれた**。
「差がある」と言う前に、必ず同じもの同士を測って誤差の床を出すこと。

## ② むらさきの「つかめない」

### 調べた結果：窓は効いていた。**弾かれたときに何も起きていなかった**

実測（練習場②で断末魔を掛け直して先頭から計測）:

```
設定 guardSec=0.85 / 予告=0.80    実測 つかめない 0.82秒 / 予告終了 0.82秒
```

穴は無く、窓は設計どおり効いている。掴めなかったのは事実。**では何が「普通につかめた」のか。**
原因は2つあり、どちらも「掴めない瞬間が体験として存在しない」ことに行き着く。

1. **弾かれても何も起きなかった。** `press()` は掴めない獲物を候補から外すだけで、
   そのまま `jab()`（突き）に落ちていた。プレイヤーから見ると「射程外だった」「敵が居なかった」と
   完全に同じ挙動＝失敗したことが分からない。数フレーム後に窓が明けて掴めるので、
   体験としては「普通につかめた」になる。
2. **掴める合図が点きっぱなしだった。** よろけの輪（青白＝「これは自分の獲物」）は
   予告中も青白のままで、本体の紫点滅と真っ向から矛盾していた。

### 直し方

- **輪を紫にして脈打たせる**（`Run` のよろけ更新）。掴める記号を必ず消す。実測で予告中の100%が紫。
- **手を出したら弾かれてしびれる**（`billiard.blockedGrab`）。
  - 主人公は敵と反対方向へ弾かれる（`knockback 300 / 0.18秒`）
  - `stunSec 0.30` のあいだ動けない・掴めない。主人公が紫に点滅する
  - 敵から主人公へ紫の電撃が1本＋主人公から放射状に5本＋140ms後に3本
  - 音は新規 `numb`（矩形波の唸り＋低いノコギリ＋ノイズ2枚＋弾かれる「ぼよん」）
  - **ダメージは0**。`cooldownSec 0.5` 以内の2回目は従来どおり突きへ落とす（連打で毎回止めない）

> 「つかむタイミングを逃した罰がほしいが、あまり厳しくすると難易度が上がってしまうのも困る」

に対する答えがここ。**払わせるのは体力ではなく時間と間合い**にした。
実測：被ダメージ 0 / しびれ 0.30秒 / 距離 70px→95px（25px 押し戻される）。
掴み直すには近づき直すしかないので、失敗は確実に伝わるが理不尽にはならない。

### 罰の重さ — 実測でどこまで押さえたか

自然なプレイ（ボット＝**ボタンを押しっぱなしのワーストケース**）で弾かれた回数：

| seed | 罰ON 生存 | 弾かれた | 罰OFF（しびれだけ止めた対照）生存 |
|---|---|---|---|
| 42 | 40s | 3.00回/分 | 168s |
| 7 | 255s | 7.53回/分 | 154s |
| 99 | 133s | 9.47回/分 | 142s |

⚠️ **生存時間では判定できない。** 罰ONの中だけで 40〜255秒（6倍）ばらつくのに対し、
ON平均143秒 vs OFF平均155秒の差はそれより小さい。ボットの死亡時刻の分散が支配的で、
6本では有意差を出せない（メモリ「ボットは死ぬ時刻がランごとに大きくぶれる」のとおり）。

**判定できるのは直接の費用のほう**：5.8〜11.1回/分 × 0.30秒 ＝ **1.8〜3.3秒/分
（プレイ時間の3〜6%）動けない**。これが上限で、ボタンを押しっぱなしにしない人間はもっと少ない。

天井をさらに下げるため、**罰は1つの紫の窓につき1回だけ**にした（`e.grabBlocked`）。
窓0.85秒に対しクールダウン0.5秒なので、以前は1つの窓で最大2回しびれ得た。
「1回のミス＝1回の罰」に揃えることで、押しっぱなしのプレイヤー（＝小さい子）が
動けない時間だけを積むことがなくなる。

### 練習場②の置き位置を直した

旧実装は的を `px + 120` に置いていた。掴める距離は78pxなので、
0.85秒の窓のうち0.28秒は**歩いているだけで過ぎていた**。`px + 70`（最初から手が届く）へ変更。

### 「黄色に点滅してから消滅」について（趣味判断）

これは別の仕組み（よろけの時間切れ）で、**ゲーム内キー8で今も切り替えられる**。

- 消滅（既定）… 静かに消える。弾を1つ失うだけ＝罰は機会損失のみ
- 強化復活 … HP45%・速度1.25倍・ダメージ1.25倍で戻ってくる＝はっきり罰があるが敵は減らない

②の罰（弾かれる）を入れた今、時間切れにも罰を足すと「失敗のたびに止まる」ゲームになる。
**まずは消滅のままを推奨**。実プレイで物足りなければキー8で強化復活を試して選ぶ形にした。

## ③ ばくだんの たま（時間内に投げ切ったボンバ）

`BALANCE.deathThroe.fuse.throwSpec = 'bomb'` で、掴んだボンバの弾に `spec:'bomb'` が付く。
らいこうだん／ほのおだんと同じ特殊弾の経路に乗るので、新しい仕組みは増やしていない。

| 項目 | 値 | 理由 |
|---|---|---|
| `pierceHp` | 1 | **貫通しない**。最初に触れた1体で爆発して終わる＝爆弾の動き |
| `blastRadius / blastMax` | 140px / 12体 | 健常な敵も面で巻き込む＝「ダメージ大」の実体 |
| `radiusMul` | 2.2 | よろけている獲物の連鎖炸裂は 76×2.2＝167px |
| `bossHpRatio` | 0.10 | らいこうだん0.30・ほのおだん0.12 の下。切り札の座は譲らない |
| 当たり判定 | 30px | ボンバ本体は半径7。そのままだと普通の弾より細くなる |
| 投げ出しの演出 | 白フラッシュ**なし** | ボンバを掴むたび起きる＝頻度が高い。振幅は頻度と逆相関 |

- 外れて寿命が尽きた弾もちゃんと爆発する（「投げ損」を作らない）
- 溜めると従来どおり手の中で爆発する（＝失敗）。この二択が「急いで投げる」を作る
- 実測（練習場③）: 手の中 `spec='bomb'` → 投げた弾 `spec='bomb'` → 敵に命中で爆発1回・**7体撃破**

### ⚠️ 初版は「ふつうの弾より弱い」爆弾だった

自然なプレイ250秒の実測で **1投あたりの撃破が ばくだん1.50 < ふつうの弾2.05** と逆転していた。
原因は爆弾が貫通せず「最初に触れた敵」で爆発すること。そこは**主人公に近い側＝自分のキル圏の
内側**で、常に掃除されているので巻き込む相手が2〜3体しか居ない（半径140pxは画面の19%）。

→ `blastRadius 140→185`（画面の35%）・`blastMax 12→16`・`radiusMul 2.2→2.6`。
「威力を上げる」ではなく**面を広げる**のが効く、というのは R25 の格の炸裂で既に出ていた結論と同じ。

自然なプレイでの頻度（ボット・250秒）：ボンバを導火線つきで掴んだ **2.9回/分**、
そのうち投げ切れた **1.0回/分**、手の中で爆発 **1.9回/分**。
＝ 報酬（ばくだん）は毎分1回の帯。らいこうだん（150〜300秒に1回）より下、
ふつうの投げ（36回/分）よりずっと上に置いた。

## 検証

```
node vortex/dev/test-core.js                     # 3件ぶんの恒久ガードを追加済み
node vortex/dev/validate-data.js
node vortex/scratchpad/cdp-practice.mjs 42 60 nogod   # れんしゅうじょうの通し（EXCEPTIONS=0）
node vortex/scratchpad/cdp-r29w2.mjs 42               # ①のスペクトル実測／②の窓と罰／③の爆弾弾
node vortex/scratchpad/cdp-r29w2-play.mjs 42 420 nogod # 自然なプレイでの発生頻度
```

`test-core` に入れた恒久ガード:

- ONのプリセットは**1発の音も締めの音も全部ちがう**こと（①の再発防止）
- つかみ失敗の罰に `damage` を含めない・しびれは0.5秒以内（②が難易度を上げないための上限）
- `fuse.throwSpec` が実在する特殊弾を指す／ばくだんは貫通しない／ボス特効はらいこうだん未満

### 実装で踏んだ穴

- 音の差を **AudioContext の createGain を横取り**して測ろうとしたら、Phaser が別の
  AudioContext を持っているため**別文脈の GainNode** を掴んで `InvalidAccessError` で落ちた。
  → `Sound.debugTap()` を追加して出力点を正しく1つ外へ出す（ゲーム側の音の経路は変えない）。
  ESモジュールはキャッシュされるので、動的 import で得られるのはゲームと同一のインスタンス。
- 主人公の当たり判定 `run.player` は**ただのオブジェクト**で、絵は `run.playerImg`。
  `run.player.setTint` は存在しない（`updatePlayer` は `billiard.update` より前に走るので、
  ここで塗った色はそのフレーム有効）。
- ②の窓を途中から測ると短く見える（0.85秒の窓を0.53秒から数えていた）。
  掛け直して**先頭から**測ること。
