# R30 マオウレクスの分離／再合体

実プレイFB（2026-08-24）:

> マオウレクスを分離させて。まずマオウレクスの体力を1.2倍に。体力が半分になると、上半身と下半身とに
> 分かれて二体で別々に襲ってくる。移動スピードも速い。ロケットパンチ？は上半身が、ミサイルは下半身が
> 出す。体力が三分の一になると、再び合体して体の色がメタリックパープルに変化。胸からレーザービームを
> 照射する。ド派手な演出にして。破壊力も作中最大ダメージに。再合体および色の変化の様子は、プレーヤーに
> 見せるようにして。

---

## 1. 設計の芯：HPは最後まで1本

いちばん大きな判断は「**下半身にHPを持たせない**」こと。

- **判断** — 下半身（lower）はダメージを一切受けない砲台にする。弱点コアは最後まで上半身の胸にだけある。
- **根拠** — 2体にHPを持たせると「どちらを先に倒すか」という別のゲームが始まってしまう。この作品の
  合格基準は「攻撃の爽快感」と「攻撃を受けた緊張感」の最大化であって、標的選択の戦略性ではない。
  狙う場所が試合中に増えると、ビリヤード攻撃（掴む→溜める→投げる）の照準が散る。
- **事実** — 三分の一で必ず再合体する仕様なので、仮に下半身を倒せても「倒しきる前に合体で復活」という
  一番しらける形になる。下半身は最初から倒せないほうが筋が通る。

副次的な利点として、HPバー・撃破処理・`releaseEnemy` の全経路が既存のまま1体ぶんで足りる。

| | 上半身（boss本体） | 下半身（lower） |
|---|---|---|
| HP | 24000（1本だけ） | 1e9（`weakGate` が必ず弾く） |
| 弱点コア | あり（胸・`weak`） | なし |
| 攻撃 | ロケットパンチ／ナックル／ノヴァ／バルカン | ホーミングミサイル斉射のみ |
| 移動 | `chaseSpeed 68 × 1.6` | `lowerSpeed 122`（本体より速い） |
| 体当たり | `bodyDamage 30` | `lowerBodyDamage 34` |

絵も新規に作っていない。rig の `legL` / `legR` を lower の座標へ付け替えるだけ（`updateDisp` の
パーツ配置ループ1か所の分岐）。破棄経路も既存のまま済む。

## 2. 3つの節目

| HP | 何が起きるか | 尺 |
|---|---|---|
| 50%（`split.hpRatio`） | 分離。暗幕＋スロー0.42＋白フラッシュ＋「マオウレクス ぶんりつ！」 | 1.5s |
| 33%（`merge.hpRatio`） | 再合体。下半身を本体へ吸い寄せ、接触の瞬間にメタリックパープルへ変色 | 2.4s |
| 以降 | 胸部レーザー（`chestLaser`）が攻撃ローテに入る | 溜め1.5s＋薙ぎ1.1s |

- 分離は **phase2 と同じ節目にまとめた**（`phase2HpRatio === split.hpRatio`）。節目は多いほど1つ1つが
  薄まるので、「激怒」と「分離」を別々には置かない。
- 再合体は `contactAt = 0.62` の位置で色が変わる。カットシーンの途中に置くのは、**変色そのものを
  見せる**ため（終わり際に変えると暗幕が明ける動きに紛れる）。

### 攻撃ローテの切り替え

```
attacks       (通常)  laser, knuckle, wirearm, missile, nova
attacksSplit  (分離)  wirearm, knuckle, nova, wirearm, vulcan   ← missile が無い＝下半身の担当
attacksP3     (合体後) chestLaser, wirearm, nova, chestLaser, missile
```

`missile` を分離中の上半身の表から外したのが「ミサイルは下半身が出す」の実体。ミサイルの発射関数は
`fireMissilesFrom(ox, oy, ang)` に一般化して、下半身のAIから同じ弾を撃たせている。

## 3. 胸部レーザー（作中最大ダメージ）

- damage **80**。次点はロケットパンチの 64、その次がダッシュ体当たりの 52。
- プレイヤー HP は 140 なので、満タンからの一撃死はしない（この作品の設計上限）。
- 溜め1.5秒のあいだ、光が**胸のコアへ収束する**（半径150→26px）。撃つ前から場所が分かる＝避けられる。
- 発射時：白フラッシュ0.49・シェイク600ms/14px・`bigBoom` + `thunder` + `fireBlast` の3重・
  フリーズ0.10秒・反動。薙ぎは −58°→+58°、長さ560px・幅74px。

### 「プレーヤーに見せる」の実測

ユーザー指示のいちばん重い一行は「再合体および色の変化の様子は、プレーヤーに見せるようにして」。
これは**主人公がボスから離れている最悪ケース**で測らないと意味がない（近くに居るときしか見えない
演出は「見せている」ことにならない）。主人公をボスから 400px／420px 離した状態で節目を跨がせた:

| | 実測 |
|---|---|
| 分離カットシーン中にボスが画面内だったフレーム | **87 / 91** |
| 再合体カットシーン中にボスが画面内だったフレーム | **166 / 166** |
| **色が変わった瞬間**のボスの画面内座標 | **(308, 180)** / 画面 640×360 ＝ ほぼ画面中央 |
| カットシーン後にカメラが主人公へ戻ったか | 主人公が画面中央（325, 185） |

この数字はカメラをカットシーン中だけボスへ預ける実装（§5(e)）を入れてから取ったもの。
入れる前は、再合体の瞬間ボスは**画面左端の外**にいた。

## 5. 途中で踏んだ欠陥

### (a) 再合体が永遠に終わらない

`update()` の `if (split && !phase3 && ...) startMerge()` に**入った印がなかった**ため、
`startMerge` が毎フレーム呼ばれ、`stateT` と `cineStage` が毎フレーム巻き戻っていた。
カットシーンには入るのに `phase3` に一生ならない。`merging` フラグで解決。

教訓は R21 から変わらない ——「**節目に入ったことを記録しない遷移は、節目に入り続ける**」。
`enterPhase2` は先頭で `phase2 = true` を立てていたので同じ罠を踏んでいなかった。

### (b) 計測器：ページ内 `setTimeout` の絞り込み

headless Chrome ではバックグラウンド扱いのページの `setTimeout` が1秒へ丸められ、
20ms のつもりの計測ループが実時間で数百秒かかっていた（1回目の実行が7分でE段まで到達）。
`--disable-background-timer-throttling` ほか2フラグで解決。

### (c) 計測器：密着していると弾が数えられない

下半身は主人公を追うので密着する。密着すると砲口で生まれたミサイルがその場で主人公に当たって消え、
「本数が増えた」を検出できず斉射が1回しか数えられなかった。R29 でつなみウェーブを「0発」と
誤判定したのと同じ罠。計測中は毎フレーム主人公を320px引き離す。

### (d) 脚の開き幅（実装中に発見）

`p.ox * ls * spread` と書くと、拡大スケールと開き係数の両方が掛かって脚が392px離れる
（画面幅640pxより広い）。`p.ox * s * spread` が正しい。

### (e) いちばん重い欠陥：カットシーンが画面外で起きていた

作り終えて実測したら、再合体の瞬間ボスは**画面左端の外**にいた。カメラは主人公を追い続けるので、
ボスから離れた位置で節目を迎えると、暗幕とテロップだけが出て肝心の変色は見えない。
ユーザー指示の「見せるようにして」を満たしていなかった。

対策：**カットシーンの1.5〜2.4秒だけカメラを主人公から預かり、上半身（分離中は上下の中点）へ寄せる**。

- ズームは触らない。`setScrollFactor(0)` の暗幕・テロップがズームで縮み、画面端が空くため。
- 寄せる速さは**実時間**（`run.realDt`）で詰める。スローモーション中でもカメラだけは間に合わせる。
- カメラを預かっているあいだは主人公を無敵にする。画面の外にいる自分が理不尽に削られるのが
  一番しらける（ボスの体当たりは既に止めてあったが、雑魚は殴ってきていた）。
- 返却は `finishSplit` / `finishMerge` / `endFight` / `destroy` の全経路＋`update` の保険
  （カットシーン以外の状態でカメラを預かったままなら即返す）。預かりっぱなしは操作不能に見える。

⚠️ トレードオフとして、その 1.5〜2.4 秒は**主人公が画面に映らない**。無敵にしてあるので危険は
無いが、体感が悪ければカメラの目標を「ボスと主人公の中点」へ寄せる余地がある（ただし縦 360px の
画面では両方は入りきらないので、優先はボス側）。

## 6. 恒久ガード（`dev/test-core.js` に追加）

- マオウレクスのHPが 24000（1.2倍）である
- 分離は phase2 と同じ節目・分離(0.5) は再合体(0.3333) より手前
- `attacksSplit` に `wirearm` が有り `missile` が無い／`attacksP3` に `chestLaser` が有る
- `attacksSplit` / `attacksP3` の全攻撃名が maou に実在する（綴り違いの無音不発を防ぐ）
- 分離した上半身・再合体後・下半身のいずれも本体より速い
- 分離1.5s以上／再合体1.5s以上の尺があり、変色がカットシーンの途中で起きる
- 胸部レーザーが**全ボスの全攻撃で最大ダメージ**、かつプレイヤーHP未満、溜め1.0秒以上

## 7. 申し送り

- 分離中の下半身は「脚だけ」なので、実プレイで**下半身だと読めるか**は息子さんのFB待ち。
  読めなければ `lowerScaleMul`（現1.55）を上げるか、下半身にも独自のグロー色を与える。
- 下半身は倒せない（弾く演出だけが返る）。「攻撃しても無駄」が伝わらない場合は、
  弾いたときのテキストを出す（現在は `deflect` の「カキン！」演出のみ）。
- 再合体後の通常弾（`missile`）は本体から出る。分離中との対比が薄いなら `attacksP3` を
  胸部レーザー寄りにさらに寄せる余地がある。
