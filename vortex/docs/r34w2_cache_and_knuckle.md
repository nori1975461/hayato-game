# R34 Wave2 「音楽が全然変わってない。私が見てるURLが違うのか？」の調査（2026-08-26）

実プレイFB：

> 音楽が全然変わってないのだが。本当に変えたのか？ナックルウェーブやワイヤーアームも
> 攻撃音や発射音がなにもかわっていない。ナックルウェーブやワイヤーアームの速度も
> 変わっていない。なにを変えたの？私が見てるURLが違うのか？徹底的に調査して。

## 1. 結論：3つの別々の話が混ざっていた

| 指摘 | 実際 |
| --- | --- |
| 音楽が変わってない | **コードは確かに変わっている**（実測は下記）。ただし届いていない可能性が高い作りだった |
| ナックルウェーブの音が変わってない | **指摘のとおり。一度も変えていなかった** |
| ワイヤーアームの音が変わってない | 音は R31 で作り直し済み。ただし **R31〜R33 は射出が0回**で、一度も鳴っていなかった |
| どちらも速度が変わってない | **指摘のとおり。R29 の値のまま**（トマホーク178 / 伸長1080） |
| URLが違うのか | **URLは正しい**。`REMOTE_EQ_LOCAL=YES`／公開URLに新コードが載っていることを実測 |

## 2. 「届いていない」の正体：キャッシュを破っていたのは main.js だけだった

`vortex/index.html` は次の1行でキャッシュを破っていた。

```html
<script type="module" src="src/main.js?v=20260826-2"></script>
```

しかし main.js が import する**27本のモジュール**（`sound.js` / `balance.js` / `boss.js` …）は
URLが一度も変わらない。GitHub Pages は `Cache-Control: max-age=600` を返すので、
ページを開きっぱなしにしていれば（ゲームは普通そうする）古いモジュールを使い続けられる。
＝**「新しい main.js ＋ 古い sound.js」という混ざった状態**が成立してしまう。

### 直し方：importmap で全モジュールに `?v=` を付ける

`node vortex/dev/stamp-cache-bust.js` が `index.html` に importmap を書き出す。

```html
<script type="importmap">
{ "imports": { "./src/audio/sound.js": "./src/audio/sound.js?v=20260826-3", ... } }
</script>
```

- import 文に直接 `?v=` を書くと毎回27ファイルが差分に出る。importmap なら **index.html の1ブロックだけ**で済む
- 仕様上、相対指定子は「参照元URLで解決 → その絶対URLを importmap のキーと突き合わせ」の順で処理されるので、
  キーを `./src/...` の相対で書けば公開先（`/hayato-game/vortex/`）でもローカル（`/vortex/`）でも同じ1ファイルが効く
- importmap 非対応のブラウザは無視するだけ（＝従来どおり動く）ので安全に落ちる

**実測**：モジュール取得 27本／うち `?v=` 付き **27本**（`scratchpad/cdp-r34w2-verify.mjs`）。

### あわせて：タイトルに版番号を出した

左下に `v20260826-3`。`src/data/version.js` の `BUILD` と画面の数字が違えば、
それは**間違いなくブラウザのキャッシュ**＝ユーザーが自分で判別できる。
（`Ctrl+Shift+R` で強制再読み込みすれば直る）

## 3. BGMは本当に変わったのか：発音予約を1個ずつ数えた

「差分がある」だけでは根拠にならない（差分があっても鳴っていなかった実例を R29W2 と R34 で踏んでいる）。
AudioContext を差し替えて、**鳴らそうとした音符を1個ずつ記録**して新旧を並べた
（`scratchpad/measure-maou-bgm.mjs`）。

| | 変更前(pre-R34) | 変更後(HEAD) |
| --- | --- | --- |
| 1周の音符の数 | 264 | **342**（+30%） |
| 1周のノイズ打（打楽器）の数 | 21 | **53**（+152%） |
| 1周の長さ | 22.86秒 | **20.0秒**（84→96BPM） |
| 小節ごとの最低音Hz | 55, 43.7, **61**, 49, … | 55, **61**, 43.7, 49, … |
| 長三和音(C)が来る時刻 | **5.71秒** | **2.50秒** |
| 冒頭400音の並び | — | **別物** |

＝ BGM は客観的に変わっている。ユーザーに届いていなかったとすれば理由は §2 のキャッシュ。

## 4. ナックルウェーブ：ここは本当に何もしていなかった

実装を読み直したら指摘のとおりだった。

```js
// 旧: R29 の汎用ミサイル音を3つ重ねているだけ
whiteFlash(0.34); Sound.sfx('knuckle'); Sound.sfx('missileFly'); Sound.sfx('shoot');
```

- `knuckle` は **主人公が玉を掴む音**と同じもの（`billiard.js` が同じ名前を鳴らしている）
- 飛んでいるあいだ **完全に無音**（R31 で作った SAM の3点セットは `missile` 側にしか繋いでいない）
- 主人公に直撃しても **爆発も爆発音も起きない**
- 弾速 **178px/秒**。主人公の移動が 148px/秒 なので **1.20倍＝ほぼ並走**。通常ミサイルは 480

### 直したこと

専用の3点セットを新設した。SAM の流用にはしていない。
実物の BGM-109 トマホークは**亜音速の巡航ミサイル**で、ブースターで撃ち出したあと翼を開いて
ターボファンで飛ぶ。SAM の「超音速のクラック」ではなく**低いジェットのうなり**が主役になる。
（音色そのものの録音資料は確認できていないので、ここは機構からの再構成＝**推測を含む**）

- `knuckleWave()` … ①両拳の巨大な金属クラッシュ ②発射管が開く ③**7本が0.035秒ずつずれて点火**
  - ③をずらすのが要点。同時に鳴らすと1発の爆発に聞こえて「7本撃った」が数えられない
- `tomahawkFly()` … 巡航中のターボファンのうなり＋翼が切る風（近いほど音程が上がる）
- `tomahawkBoom()` … 着弾。SAM より低く・遅く・長い（重い弾頭を運ぶミサイルなので）

## 5. 速度

| | 変更前 | 変更後 | 根拠 |
| --- | --- | --- | --- |
| トマホーク | 178 | **320**（2.16倍） | 主人公148の1.20倍しかなかった。通常ミサイルは480 |
| ワイヤーアーム 伸長 | 1080 | **1450**（+34%） | R29 のまま据え置かれていた |
| ワイヤーアーム 射程 | 330 | **360** | 同上 |
| ワイヤーアーム 追尾 | 64°/秒 | **54°/秒** | 速くしたぶん緩める |

**理不尽にしない根拠（恒久ガードに数式で入れてある）**：
トマホークは7本を150°扇状に撒くので隣接弾の角度差は25°＝距離200pxで隙間86px。
主人公は320px/秒の弾が200px飛ぶ0.63秒で93px動ける＝**まだ抜けられる**。
弾は直進（ホーミングなし）でダメージ22も据え置き。
ワイヤーアームも damage 64 は据え置き（緊張感は被弾量ではなく「避けた回数」で作る）。

**出番も増やした**：再合体後の攻撃表 `attacksP3` の `nova` を `knuckle` に入れ替え。
本体の表で4番目・分離中の表で2番目にしか居らず、実測で**発射は1〜2回だけ**だった。
音と速度を作り直しても、出番が1回では聞き分けられない。
